# Minially v1.2 UX 개선 검토

로컬 확인용 변경이며 Git 커밋·푸시 및 GitHub Pages 배포는 실행하지 않았습니다.

## 발견한 문제와 반영 내용

| 확인한 문제 | 반영한 동작 |
|---|---|
| 등록·수정·프리셋 저장·복사의 버튼 이름이 서로 달랐음 | 등록 / 변경사항 저장 / 프리셋 저장 / 복사 / 이동 / 추가로 정리함 |
| 작성 중 취소와 빈 화면 닫기를 구분하지 않았고 하단 취소 버튼이 확인 경로를 우회했음 | 변경한 입력이 있을 때만 계속 작성 또는 등록 취소를 표시함 |
| 여러 날짜 등록으로 이동하면 제목·메모 등이 사라졌음 | 같은 등록창 안에서 날짜를 선택하고 입력 내용으로 여러 일정을 등록함 |
| 복사·이동 창이 비동기 저장을 기다리지 않고 닫혔음 | 실제 저장 후 닫으며 실패하면 선택 내용과 오류 메시지를 유지함 |
| 프리셋 즐겨찾기가 최근 사용에도 중복 노출됐음 | 최근 사용에서 즐겨찾기를 제외함 |
| 프리셋 추가·수정 후 폼이 남고 편집 상태가 불명확했음 | 저장 후 목록으로 돌아가며 같은 ID를 갱신함 |
| 검색 결과 편집 후 검색어와 이전 위치를 잃었음 | 편집을 마치면 검색어와 이전 화면으로 복귀함 |
| 새 일정의 날짜를 바꿔 등록해도 달력 선택 날짜가 그대로였음 | 등록한 날짜를 선택하고 해당 월을 표시함 |
| 월 이동 시 목록의 선택 날짜와 표시 월이 달랐음 | 이동한 달의 같은 날짜를 선택하며 말일은 해당 달의 마지막 날로 맞춤 |
| 일정 변경과 실행 취소 기록을 별도로 저장했음 | 하나의 데이터베이스 트랜잭션에서 저장·복구함 |
| 목록에서 삭제 전 확인이 없었음 | 확인 후 삭제하고 일정·할 일은 실행 취소로 복구할 수 있게 함 |
| 저장 중에도 일부 조작이 가능했고 빠른 입력은 실패 시 사라졌음 | 중복 조작을 막고 실패한 입력을 유지함 |
| 긴 제목과 작은 터치 영역 때문에 모바일에서 사용하기 어려웠음 | 목록 제목 줄바꿈, 주요 버튼 44px, Safe Area와 화면 높이 변화 대응을 반영함 |
| 모바일 화면 축소 시 등록 버튼이 화면 밖으로 밀렸음 | 편집 영역의 스크롤 구조를 수정함 |

## 명칭과 데이터 호환성

- 사용자에게 보이는 '자주 쓰는 문구'를 '프리셋'으로 통일함. 제목 오른쪽 버튼, 목록·검색·편집·알림·접근성 레이블에 반영함.
- 프리셋은 제목 문구를 저장하는 기능으로 유지함. 날짜·시간·반복 설정을 저장하는 새 템플릿 기능은 추가하지 않음.
- 기존 메모 항목은 삭제하지 않으며 저장된 메모 선택 및 기존 항목 편집을 유지함.
- `DayFlowDB`, `presets`, 기존 ID·필드·백업 구조를 유지함. 추가한 카테고리 순서와 할 일 실행 취소 기록은 선택 필드이며 기존 저장소를 재생성하지 않음.
- 카테고리 삭제 시 일정, 반복 일정의 예외, 기본값, 실행 취소 기록의 참조를 같은 트랜잭션에서 미분류로 변경함.
- 백업 복원 후에는 복원 전의 실행 취소 알림을 지워 이전 작업이 복원한 데이터에 적용되지 않도록 함.

## 화면 점검 범위

실제 앱에 연결된 캘린더·할 일·일정 등록/수정·여러 날짜 선택·복사/이동·프리셋·카테고리·검색·설정·확인창·알림을 점검함. 별도 캐릭터 화면은 구현되어 있지 않음. 프로젝트 관리용으로 남아 있지만 현재 앱에서 연결하지 않는 컴포넌트는 새로 연결하거나 확장하지 않음.

## 검증

- 설치된 Chrome을 사용하는 Playwright 자동화로 주요 기능 전체 25개 시나리오를 실제 실행했으며 모두 통과함. 테스트마다 독립된 브라우저 저장소를 사용함.
- 등록창·프리셋 선택·카테고리 선택을 각각 20회 반복했으며 오버레이 1개와 일정한 배경색, 닫은 뒤 포커스·스크롤 복구를 확인함.
- 빈 초안 닫기, 변경한 초안 계속 작성·버리기, 연속 등록 후 닫기, 중복 클릭 방지, 프리셋·카테고리·설정 미저장 입력 보호를 확인함.
- 여러 날짜 등록 시 제목·시간·메모 보존, 일정·할 일 삭제 후 실행 취소, 검색 편집 후 검색어 복귀를 확인함.
- 저장·삭제 오류를 주입해 일정 저장·복사·이동·카테고리 삭제의 원자적 롤백과 재시도를 확인함.
- 구형 프리셋 변환, 동일 ID 편집, 기존 일정·반복 관련 데이터 보존, 새로고침, JSON 다운로드·복원과 잘못된 복원의 롤백을 확인함.
- 320px 폭과 축소된 화면 높이에서 등록 버튼 노출, 가로 스크롤, 키보드 포커스 순환을 확인함. 데스크톱·모바일 크기의 스크린샷도 확인함.
- 타입 검사(`npm run lint`)와 변경 파일 공백 검사(`git diff --check`)를 통과함.
- GitHub Pages용 프로덕션 빌드(`npm run build:pages`)를 통과함. 기존 배포 설정은 변경하지 않음.
- 폼 입력·선택·등록·취소·복사·이동·삭제·복귀는 실제 클릭·키 입력으로 실행함. 실패 주입, 저장값 비교, 일부 백업 왕복 검사는 브라우저 안의 저장 API로 검사함.

실제 휴대폰의 소프트 키보드, iOS Safari/PWA 설치 및 운영체제 뒤로가기는 물리 기기에서 검증하지 않음. Chrome에서 모바일 크기·화면 높이 변화·브라우저 뒤로가기를 별도로 검사함. 공개 페이지 새 버전 확인은 배포를 실행하지 않아 해당하지 않음.

## 프리셋 블록과 선택형 날짜·시간 추가 개선

- 메인 상단의 일정 등록·프리셋 진입으로 모으고 헤더 등록, 목록의 추가 아이콘·빠른 등록 폼, 모바일 하단의 중복 등록 버튼을 제거함.
- 메인 프리셋 화면에서 여러 프리셋과 단어를 블록으로 조합해 바로 등록하거나 일정 설정으로 넘어갈 수 있게 함.
- 조합한 제목 블록과 저장된 프리셋 목록 모두 마우스·터치 드래그 및 방향키 정렬을 지원함. 선택 블록은 개별 제거할 수 있음.
- 일정의 선택 필드인 titleBlocks에 조합 정보를 저장해 재편집·복사·백업 시 블록 구성을 유지함. 기존 일정 제목은 변경하지 않으며, 블록 정보가 없는 이전 데이터도 그대로 읽음.
- 새 일정의 카테고리를 선택하세요 상태로 두고, 등록 화면에서 새 카테고리를 추가해 바로 선택할 수 있게 함.
- 새 일정은 종일 체크 해제, 09:00~10:00으로 시작함. 시·5분 단위 선택기를 사용하며 기존의 1분 단위 저장 값은 열기·메모 수정만으로 반올림하지 않음.
- 날짜·시간의 직접 입력칸을 제거함. 활성 등록·복사·이동·여러 날짜·할 일 화면의 날짜는 연·월·일 선택 달력을 사용함. 열린 달력은 Escape·뒤로가기로 먼저 닫힘.
- 등록 중 확인 버튼을 등록 취소로 바꾸고 수정 화면은 수정 취소로 구분함.
- 새 공통 컴포넌트: src/components/common/TitleBlockEditor.tsx, DatePicker.tsx, TimeField.tsx. 정렬 처리: src/hooks/useDragOrder.ts. 신규 검증: tests/preset-blocks.spec.ts, tests/helpers/date.ts.
- Chrome의 실제 마우스 드래그와 모바일 터치 이벤트로 두 정렬 경로를 검증함. 등록 기본값, 선택 전용 날짜·시간, 직접 카테고리 추가, 재편집·새로고침·JSON 왕복을 포함해 전체 25개 검사를 통과함.
- 전체 회귀 25개를 통과한 뒤, 할 일 날짜 달력의 Escape·뒤로가기·바깥 클릭 및 초안 유지 검사를 추가로 실행해 통과함.
- 날짜 달력은 모달 안팎에서 다른 화면을 닫지 않고 먼저 닫히도록 처리함. 모달 밖의 달력은 페이지 스크롤과 다른 입력을 잠그지 않음.
- 최신 코드의 타입 검사와 GitHub Pages용 프로덕션 빌드까지 통과함. Git 업로드·배포는 실행하지 않음.
