# Minially v1.3 모바일 UX 검토

## 구현 범위

- 640px 미만 화면에서 월간 달력 날짜 선택 시 날짜별 바텀시트를 표시한다. 기본 높이는 화면의 62%, 키보드를 포함한 실제 사용 가능 영역의 80%를 상한으로 사용한다.
- 데스크톱의 달력 아래 일정 목록과 기존 등록·복사·이동·검색·여러 날짜 등록은 유지한다.
- 시트 안에서 카테고리형/목록형을 전환하며 마지막 선택을 앱 설정에 저장한다. 시간 지정 일정이 먼저 나오고, 같은 시작 시간 및 시간 없는 일정에는 저장된 수동 순서를 적용한다.
- 카테고리형은 사용자가 지정한 카테고리 순서를 따르고, 미분류 그룹은 마지막에 표시한다.
- 모바일 달력에는 중복 없는 카테고리 점을 최대 3개와 초과 개수로 표시한다. 미분류는 회색이며, 중요 일정이 있으면 작은 별을 표시한다.
- 중요 일정은 등록·수정 화면의 별 토글로 설정하며, 시트·데스크톱 달력 및 목록·검색에 별과 굵은 제목을 표시한다. 중요 여부가 정렬 순서를 바꾸지는 않는다.
- 빠른 등록은 제목만 입력해도 저장할 수 있다. 시간 지정 시 기존과 같이 09:00~10:00, 5분 단위 선택을 제공한다. 일반 상세 등록의 기존 기본값은 유지한다.
- 상세 옵션에서 매일·평일·매주·매월 반복과 선택 전용 종료일을 설정한다. 기존 반복 회차를 수정할 때는 해당 날짜만 변경하며, 원본 일정의 반복 설정은 유지한다. 반복과 여러 기준 날짜의 동시 등록은 중복 시리즈 생성을 막기 위해 안내하고 저장하지 않는다.
- Enter 연속 등록, 한글 조합 중 Enter 제외, 저장 중 중복 요청 방지, 저장 실패 시 초안 유지, 저장 성공 후 제목·중요 표시 초기화를 처리한다.
- 프리셋은 시트 내부에서 검색·탭 적용·마우스 드롭·터치 드롭할 수 있다. 즐겨찾기·최근 사용·나머지 목록 사이에 같은 프리셋을 중복 표시하지 않는다. 프리셋 적용은 자동 저장하지 않으며 이전 제목 복구를 제공한다.
- 프리셋과 카테고리 관리는 기존 시트 안의 패널로 처리한다. 기존 제목 블록 조합과 프리셋 관리 기능은 상세 등록 및 메인 프리셋에서도 계속 사용할 수 있다.
- 일정 행의 핸들로 마우스·터치·키보드 순서 변경을 제공한다. 터치는 300ms 이상 길게 누른 뒤 이동한다. 다른 시작 시간 사이의 이동은 안내하고 저장하지 않는다.
- 시트에서 상세 등록·수정·복사·이동으로 전환할 때 시트를 잠시 숨겨 backdrop과 포커스 트랩이 겹치지 않게 한다. 복귀 후 시트 초안을 유지한다.
- 시트의 실행 취소 버튼을 사용하여 저장 알림이 하단 입력창을 가리는 것을 방지한다.

## 데이터 호환

- IndexedDB `DayFlowDB`의 기존 스토어와 버전 1을 유지한다. 인덱스 변경 없는 선택 필드 `isImportant`, `sortOrder`, 설정 `dayScheduleView`만 추가했다. 필드가 없는 과거 일정은 중요하지 않은 일정 및 기본 순서로 취급한다.
- 신규 사용자에게 예시 카테고리를 생성하지 않는다. 기존 카테고리를 구분 없이 지우지 않으며, 과거 localStorage에 사용자가 저장한 카테고리가 있으면 최초 이관한다.
- 반복 회차 변경은 원본 시리즈를 덮어쓰거나 가짜 일정 ID로 저장하지 않고 기존 반복 예외 스토어에 저장한다. 일정·반복 규칙·반복 예외·실행 취소 기록을 하나의 트랜잭션으로 처리한다. 새 반복 일정의 실행 취소는 해당 규칙도 함께 되돌린다.
- 카테고리 삭제는 기존 일정과 반복 예외 및 실행 취소 기록의 참조를 미분류로 바꾼다. 이후 실행 취소로 삭제한 카테고리 참조가 되살아나지 않게 한다.
- 기존 JSON 백업 형식과 새 필드의 JSON 왕복을 유지한다. 실제 사용자 데이터 초기화 및 삭제는 실행하지 않았다.

## 프리셋·카테고리 추가 요청 반영

- 메인 프리셋 버튼은 일정 저장과 분리한 프리셋 관리 화면을 연다. 그룹별 단일 프리셋 관리와 보조 기능인 블록 묶음 만들기를 제공한다.
- 묶음의 단어·순서는 선택 필드 `Preset.blocks`에 보관한다. 기존 단일 문구와 ID는 유지하며, 묶음 수정 시 같은 ID를 갱신한다. 원본 단어 프리셋을 수정·삭제해도 저장한 묶음과 이미 등록한 일정의 문구를 자동 변경하지 않는다.
- 일정 제목 옆 프리셋 버튼은 제목 아래 가로 그룹 탭과 목록을 펼친다. 프리셋을 선택하면 제목에 적용하고 패널만 닫는다. 기본은 제목 교체이며 이어 붙이기와 이전 제목 복구를 제공한다. 적용한 묶음의 제목 블록은 마우스·터치·방향키로 옮길 수 있다. 날짜·시간·카테고리·메모·중요 표시는 유지한다.
- 보기의 프리셋 목록은 사용자가 지정한 순서로 유지한다. 즐겨찾기와 사용 횟수·최근 사용 시각은 저장하며 관리 화면에서 정렬 기준을 고를 수 있다.
- 카테고리는 최대 10개, 기본 팔레트는 비슷한 채도의 파스텔 10색이다. HEX 및 직접 색상 선택을 유지한다. 새 카테고리 추가 제한은 UI와 IndexedDB 트랜잭션 양쪽에서 검사하여 동시에 요청해도 상한을 넘지 않는다.
- 과거 버전이 자동 생성한 항목은 ID·이름·색상·기본 표시가 원래 예시와 모두 일치하고 실제 일정·반복 예외에서 사용하지 않는 경우에만 목록에서 제외한다. 해당 원본은 저장소와 JSON 백업에 남긴다. 사용 중이거나 수정한 카테고리, 직접 만든 카테고리는 유지한다.
- 직접 추가·수정한 카테고리는 선택 필드 `isUserManaged`로 표시하여, 원래 예시와 같은 이름·색상으로 바꾸어도 사용자가 관리한 항목을 숨기지 않는다.
- 이전 데이터에 이미 10개를 초과하는 실제 카테고리가 있어도 삭제하지 않는다. 기존 항목은 편집·삭제할 수 있으며, 새 항목은 10개 미만으로 정리한 뒤 추가할 수 있다.

## 검증

- 테스트 코드를 작성하는 데 그치지 않고 Playwright를 사용해 실제 Chrome에서 클릭·입력·저장·화면 복귀·마우스 드롭·CDP 터치 드래그를 실행했다. 실제 사용자 프로필과 분리한 데이터로 확인했다.
- 첫 전체 실행은 기존 26개와 새 모바일 9개를 포함한 **35개 통과**였다.
- 입력 취소와 초안 초기화 보완 후, 관련 기존 시나리오와 추가 경계 사례를 포함한 **26개가 재검증에서 통과**했다.
- 추가 경계 사례에는 프리셋·카테고리 패널 각각 20회 전환, 미완성 HEX 취소, 일정 순서 저장 실패 시 전체 롤백, 동시 전송 중복 방지, 시트 내부 실행 취소, 반복 회차 이동·복사, 상세 연속·여러 날짜 등록 후 초안 초기화, 데스크톱 복귀 및 검색 중요 표시가 포함된다.
- 반복 설정 연결 후 관련 11개 중 10개가 통과했고, 빠른 패널 전환 검사에서 1회 예상치 않은 닫힘을 발견했다. 공통 모달 훅이 커밋된 화면 상태를 사용하도록 바꾸고 DOM의 현재 패널도 확인하여, 같은 20회 패널 전환 검사를 **3회 연속 통과**했다. 새 반복 등록의 실패 롤백·일별 표시·규칙을 포함한 실행 취소·독립 시리즈 연속 등록도 실제 Chrome에서 통과했다.
- 공통 훅 보완 후 기존 등록창·프리셋·카테고리 각각 20회 개폐, 모바일 시트 20회 개폐와 Escape·뒤로가기·초안·스크롤·포커스 복구, 새 반복 등록을 묶은 **최종 관련 3개도 통과**했다. 기존 26개와 신규 모바일 15개에 해당하는 총 41개 시나리오를 단계별로 실행했으며, 최종 보완은 영향을 받는 시나리오를 선별해 재검증했다.
- `npm run lint`와 `git diff --check` 통과. `npm run build:pages` 통과 및 PWA 서비스 워커 생성 완료.
- Chrome에서 시트 높이·내부 스크롤·320px 및 390px 화면·축소된 사용 가능 영역의 입력창과 등록 버튼을 확인했고, 생성한 모바일 스크린샷을 열어 배치도 확인했다.
- 로컬 미리보기 `http://127.0.0.1:3000/`의 HTTP 200 응답을 확인했다.
- 프리셋·카테고리 추가 요청의 새 검사 5개는 처음 실행에서 통과했다. 이후 전체 46개 실행에서 44개가 통과했고, 2개는 제거된 ‘제목 적용’ 버튼 및 관리 목록의 이전 버튼 선택자를 사용하여 실패했다. 새 흐름에 맞게 선택자를 수정했다.
- 제목 단어 목록 안정화와 모바일 제목 터치 검사를 추가한 **최종 관련 9개가 모두 통과**했다. 새 요구사항 검사 6개와 수정한 이전 검사 2개, 미저장 보호·즐겨찾기 중복 방지 검사를 포함한다. 기존 41개와 신규 6개로 총 47개 시나리오를 단계별로 실행했다.
- 로컬 3000 포트에서도 별도 Chrome 모바일 프로필로 프리셋 묶음과 제목 아래 단어 선택을 직접 실행했다. 캡처한 화면을 열어 배치를 확인했다. 실제 사용자 저장소는 사용하지 않았다.

## 확인 한계

- Chrome 모바일 에뮬레이션과 실제 CDP 터치 입력으로 검증한다. 물리 휴대폰의 소프트 키보드, iOS Safari, 홈 화면 설치 PWA의 기기별 동작은 별도 확인이 필요하다.
- 키보드 대응 자동 검증은 사용 가능 화면을 줄여 입력창·등록 버튼 노출과 내부 스크롤을 확인하는 방식이며, 실제 휴대폰 키보드 실행 결과와 구분한다.
- GitHub Pages 설정은 변경하지 않았다. 이번 변경의 커밋·푸시·공개 배포는 로컬 검토 후 진행한다.


## 가로 탭형 프리셋 그룹 개편

- 프리셋 그룹 관리와 프리셋 관리를 같은 오버레이 안의 별도 패널로 구분한다. 그룹 추가·같은 ID로 이름 수정·핸들 정렬, 프리셋 추가·수정·삭제·즐겨찾기·핸들 정렬·그룹 이동 메뉴를 제공한다.
- 가로 탭은 줄바꿈 없이 좌우 스크롤하며 선택 그룹을 자동으로 화면 안에 표시한다. 마지막 선택은 이 브라우저의 localStorage에 보관하며 새 그룹은 즉시 선택한다. 선택 그룹만 목록에 표시한다.
- 그룹 없는 과거 프리셋과 유효하지 않은 그룹 참조는 시스템 미분류에서 조회한다. 미분류는 필요한 경우에만 표시하며 이름 수정·삭제 대상이 아니다. 예시 그룹·프리셋을 만들지 않는다.
- 그룹은 기존 appSettings의 선택 필드 presetGroups에, 연결은 Preset.groupId에 저장한다. 스토어·인덱스 변경 없이 기존 IndexedDB 버전 1을 유지한다. 과거 그룹에 없는 생성·수정 시각은 읽을 때 한 번 채운다. 프리셋 ID·사용 횟수·즐겨찾기·최근 사용·기존 묶음 블록을 유지하고 JSON 백업에 함께 포함한다.
- 그룹 삭제 기본값은 프리셋 유지다. 삭제할 그룹의 포함 개수를 표시하고 미분류 이동 또는 프리셋 모두 삭제를 선택한다. 그룹 변경과 프리셋 이동·삭제는 하나의 트랜잭션이며 관리 화면에서 직전 그룹 삭제 실행 취소를 제공한다.
- 일정 등록의 패널 닫기는 X 아이콘이다. 프리셋 관리 후 작성 중 일정이 유지되며, 생성·수정 화면에는 검색창이 없다. 보기의 검색은 선택 그룹 안에서 작동한다.
- 날짜 팝업도 같은 탭형 프리셋 선택기를 사용하며, 선택 후 제목 수정·Enter 연속 등록·한글 IME 방어·포커스 유지를 지원한다. 입력창으로의 프리셋 드래그도 유지한다.
- 일정 겹침 경고와 30분 연기 동작을 제거했다. 종료 시간이 시작보다 빠른 입력 오류 검사는 유지한다.
- 새 그룹 관련 8개 Chrome 상호작용 테스트가 통과했다. 그룹 CRUD·순서·중복 이름·삭제 취소·두 삭제 방식·실행 취소·이동·즐겨찾기·백업·트랜잭션 오류 보존·제목 보호·20회 패널 개폐·모바일 가로 스와이프 및 터치 정렬·Enter 및 IME를 실제로 실행했다.
- 실제 휴대폰 OS의 키보드·iOS Safari는 미검증이다. Chrome의 모바일 화면·터치 에뮬레이션으로 검증했다. 현재 변경은 로컬 검토용이며 커밋·푸시·배포하지 않았다.

- 가로 그룹 개편 후 전체 55개 Chrome 시나리오 실행에서 49개 통과, 6개 실패를 확인했다. 초기 화면 로딩 시간 초과 1개, 이전 UI 선택자 2개, 정렬 대상이 목록 밖으로 밀리는 문제 2개, 그룹 생성 후 자동 복귀 전환에 맞지 않은 검사 1개를 조사했다. 관리 행을 줄이고 스크롤 조상을 찾아 터치 정렬하도록 보완했으며, 생성 직후 선택 그룹 관리로 복귀하는 흐름 및 관련 선택자를 수정했다.
- 이후 영향받는 13개 재검증에서 11개 통과, 남은 2개도 재검증에서 통과했다. 마지막 2개는 새로고침 후 중복 관리 진입을 제거하고 모바일 탐색 버튼은 일반 클릭, 실제 순서 변경은 CDP 터치 드래그로 검사했다. 55개 서로 다른 시나리오가 단계별로 모두 통과했으며, 최종본을 전체 55개 한 번에 재실행한 결과와는 구분한다.

- 최종 모바일 배치 확인에서 직접 입력한 단일 제목의 불필요한 블록 중복 표시를 없애고 그룹 관리 진입을 강조했다. 독립 Chrome 프로필에서 프리셋 탭 선택·즉시 적용·블록 방향키 이동·이전 제목 복구·X 닫기 후 제목 포커스·09시 입력 보존을 실제 재검증했다. 로컬 HTTP 200 및 가로 넘침 없음·오버레이 1개를 확인했고, 최종 타입 검사와 Pages 프로덕션 빌드가 통과했다.

## 프리셋 관리 사용성 후속 정리

- 기본 화면은 그룹 탭과 한 줄 프리셋 목록, 눈에 띄는 추가 버튼으로 정리했다. 그룹 바로 추가 진입을 제공하고 새 그룹 저장 후 해당 그룹이 선택되도록 유지했다.
- 수정 버튼은 글자로 표시하고 삭제·그룹 이동·순서 보조 버튼은 항목 더보기 안에 배치했다. 정렬·즐겨찾기 필터는 보기 설정, 블록 묶음 만들기는 추가 옵션에 접어 두었다.
- 추가할 때는 목록을 숨기고 입력 폼에 집중하도록 했으며 수정할 때는 수정 대상만 표시한다. 그룹 이름 편집 중에도 다른 그룹 목록을 숨긴다. 기본 데이터 저장·일정 적용 방식은 바꾸지 않았다.
- 새 데스크톱·모바일 사용성 2개를 포함한 Chrome 검사 12개와 기존 CRUD·즐겨찾기·정렬·삭제 실패 경로 3개가 모두 통과했다. 로컬 미리보기 HTTP 200, 단일 대화상자 및 가로 넘침 없음과 실제 모바일 크기의 화면 캡처를 확인했다. 타입 검사도 통과했다. 기존 사용자 프로필은 사용하지 않았고 Git 업로드는 하지 않았다.

## 일정 등록 프리셋 연속 선택 및 작은 제목 블록

- 최신 요청에 따라 선택 후 패널을 자동으로 닫던 동작을 변경했다. 등록창과 모바일 빠른 등록에서 프리셋 목록을 유지하고 여러 그룹의 항목을 차례로 선택할 수 있다. X 또는 Escape로 직접 닫는다.
- 첫 선택은 현재 제목 교체·이어 붙이기 설정을 사용하고 이후에는 자동으로 이어 붙인다. 매번 제목 입력창으로 포커스를 옮기지 않아 목록 탐색을 계속할 수 있다. 이전 제목 복구와 다른 입력값 보존은 유지한다.
- 일정 제목의 블록만 작은 칩으로 표시한다. 중복 안내·미리보기는 화면에서 숨기고 접근성 설명으로 유지한다. 짧은 한국어 단어가 잘리지 않는 폭과 약 38px 높이로 줄였으며 드래그·방향키 정렬, 직접 수정, 삭제를 유지한다. 관리 화면의 블록 편집기는 기존 크기를 유지한다.
- Chrome에서 신규 데스크톱·모바일 연속 선택, 작은 블록 크기, 실제 터치 정렬·삭제·복구, 메모·시간·중요 표시 보존, 빠른 등록의 Enter 처리와 기존 묶음 재사용을 포함한 최종 5개 검사가 통과했다. 최초 데스크톱 검사는 페이지 초기 재로딩 시간 초과로 실패했으며 재실행에서 통과했다. 모바일 화면 캡처를 직접 확인했고 타입 검사도 통과했다. 실제 사용자 데이터 초기화 및 Git 업로드는 실행하지 않았다.

## 빠른 등록 프리셋 및 독립 할 일 등록 후속 개선

- 날짜 팝업의 빠른 등록에서도 선택한 프리셋을 작은 제목 블록으로 표시한다. 내용 수정·실제 터치 및 방향키 정렬·개별 삭제를 제공하고, 블록 편집 중 Enter가 일정을 저장하지 않도록 했다. 제목 옆에 프리셋 버튼을 두고 중요 표시를 보조 옵션 행으로 옮겼다.
- 프리셋 선택 목록과 관리 화면을 오가도 작성 중인 블록·시간·카테고리·메모·중요 표시를 유지한다. 저장하면 블록과 제목을 비우고 제목 입력 포커스를 유지한다.
- 할 일 등록에서 오늘·예정을 직접 선택한다. 오늘은 오늘 날짜로, 예정은 내일 이후 선택한 날짜로 tasks에만 저장한다. 캘린더의 schedules나 연결 일정을 새로 만들지 않는다. 기존 데이터와 저장 형식은 유지한다.
- 보기 필터와 등록 구분을 별도 표시하며 모바일에서도 예정 날짜를 고를 수 있다. 저장한 항목은 해당 보기의 미완료 목록에 표시한다. 한글 IME 조합 중 Enter 방어와 저장 실패 시 초안 보존을 유지한다.
- 새 모바일 빠른 등록 1개와 모바일·데스크톱 할 일 등록 2개, 기존 연속 프리셋 선택 3개를 실제 Chrome에서 실행해 총 6개가 통과했다. 캡처한 모바일 화면을 열어 배치를 확인했으며 타입 검사와 diff 검사도 통과했다. 실제 사용자 데이터 초기화·Git 업로드는 실행하지 않았다.

## 그룹 추가 진입 및 할 일 예정 보기 동기화

- 프리셋 관리 화면의 직접 그룹 추가 버튼을 제거했다. 그룹 추가·삭제는 프리셋 그룹 관리 안에서만 제공한다. 모바일·데스크톱 기존 관리 검사 2개가 통과했다.
- 할 일 상단의 예정 보기를 선택해도 등록 구분이 오늘로 남아 날짜 선택이 숨겨지는 문제를 수정했다. 오늘·예정 보기 선택을 등록 구분과 동기화하고 입력 중인 제목·예정 날짜는 유지한다. 상단 예정 선택 후 날짜 지정·저장·새로고침 및 일정 데이터 분리를 실제 Chrome의 모바일·데스크톱에서 확인해 2개 검사가 통과했다. 타입 검사도 통과했으며 Git 업로드는 하지 않았다.

## 그룹을 오가며 단어를 조합하는 프리셋 흐름 정리

- 그룹은 프리셋 단어의 분류이며, 일정 등록에서 여러 그룹의 단어를 차례로 골라 제목을 조합하는 흐름으로 정리했다. 단어 버튼은 작은 버튼형 목록으로 표시하고 이미 추가한 단어를 표시한다. 그룹을 바꾸면 해당 그룹의 단어를 바로 볼 수 있게 검색어를 비운다. 선택한 제목 블록은 유지한다.
- 기본 동작은 첫 선택부터 제목 뒤에 단어를 추가하는 방식이다. 별도의 적용 설정을 거치지 않는다. 기존 제목 교체 기능은 접힌 보조 옵션으로 유지한다. 일정 등록과 빠른 등록에 같은 선택기를 사용한다.
- 별도의 블록 묶음 만들기 메뉴와 전용 추가 옵션 영역을 제거했다. 이미 저장된 묶음·프리셋·ID·일정·백업은 지우지 않으며 기존 묶음 편집·재사용을 유지한다.
- 새 기본 흐름과 기존 데이터·관리·저장 실패·입력 보존을 포함해 서로 다른 Chrome 검사 13개가 단계별로 통과했다. 첫 10개 실행의 기대 문구가 잘못 지정된 검사 3개를 수정하고 관련 기존 검사까지 묶은 6개 재검증이 통과했다. 새 기능 검사를 실제 Chrome 데스크톱·모바일에서 실행했으며 로컬 검토 전 Git 업로드는 하지 않았다.

## 모바일 하단 캡슐 메뉴 및 홈 제스처 안전 영역

- 모바일 하단 전체 너비 고정 메뉴를 가운데에 떠 있는 캡슐형으로 변경했다. 기존 캘린더·할 일·검색·설정 메뉴와 데스크톱 메뉴는 유지하며 선택 항목은 로즈색 배경으로 표시한다.
- viewport-fit=cover를 적용하고, 메뉴 아래 간격을 최소 16px 또는 기기의 safe-area-inset-bottom 중 큰 값으로 설정했다. 시스템 제스처 영역 위에 버튼을 두며, 제스처 자체를 막거나 별도의 투명 오버레이를 추가하지 않는다.
- 본문 하단 여백도 메뉴 높이·안전 영역·추가 여백을 합산한다. 실행 취소 알림은 캡슐 위로 올려 메뉴와 겹치지 않게 했다. 모달의 기존 안전 영역 처리와 더 높은 표시 계층은 유지한다.
- Chrome 모바일 화면에서 기본 여백·34px 안전 영역 모의 조건·320px 화면·메뉴 터치 이동·긴 목록 마지막 삭제 버튼 접근·삭제 실행 취소 알림 위치·축소 화면 등록 버튼 동작·데스크톱 표시를 확인해 최종 3개 검사가 통과했다. 생성한 모바일 화면 캡처를 열어 배치를 확인했고 타입 검사도 통과했다. 실기기 홈 제스처 자체는 미검증이며, 기존 사용자 데이터 초기화 및 Git 업로드는 하지 않았다.
